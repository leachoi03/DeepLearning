3-1. base_score: 해당 grid의 평상시 상권 체력.
base_features = (
	vg_flow				평균 유동인구
	weekday_weekend_gap		평일과 주말 유동 차이
	hourly_concentration		특정 시간대에 사람이 몰리는 정도
	card_sales_amount		카드 매출 금액
	card_sales_count			카드 결제 건수
	rainfall_mean			평균 강우량
	rainfall_impact			비가 유동/소비에 주는 영향
	bus_subway_access		대중교통 접근성
	rent_level				임대료 또는 상권 강도 대리 지표
			)
	이 변수값들을 MLP 모델에 넣어서 grid별 기본 적합도 예측.

3-2. correction_score: 해당 grid의 현재 시점 보정값.
correction_features = (
	real_time_population		현재 시점 인구 규모
	real_time_population_growth	직전 대비 인구 증가율
	traffic_congestion			교통 혼잡도
	transit_change			대중교통 이동 변화
	real_time_temp			현재 기온
	real_time_rain			현재 강우량
	event_flag				행사 여부
	holiday_flag			휴일 여부
				)
	이 변수값들은 시간 순서가 있는 시계열 데이터이기 때문에, LSTM 모델을 사용.
	(일정 길이의 시계열 흐름을 보고 현재 보정값을 예측.)

4. final_score = alpha * base_score + beta * correction_score	(alpha=1.0, beta=1.0)
	 
	base_score 높고 correction_score 높음	원래도 좋은 상권이고 지금도 좋은 상태
	base_score 높고 correction_score 낮음	원래는 좋은 상권인데 현재 상황이 안 좋음
	base_score 낮고 correction_score 높음	평소엔 약하지만 지금 일시적으로 뜨는 곳
	둘 다 낮음						장기적·실시간 모두 추천도가 낮은 곳

10. EarlyStopping(조기종료): 검증 손실이 일정 횟수 이상 좋아지지 않으면 학습을 멈춤
class EarlyStopping:
검증 성능 => patience = 12

11. TorchRegressor: PyTorch 모델 학습 과정을 하나로 묶은 클래스
class TorchRegressor:
핵심요소: 
	self.criterion = nn.HuberLoss()
	self.optimizer = torch.optim.AdamW(...)
	self.scheduler = torch.optim.lr_scheduler.ReduceLROnPlateau(...)
11-1. HuberLoss: MSE와 MAE의 중간 성격을 가진 손실 함수 
	(이상치에 MSE보다 덜 민감해서, 유동인구나 매출처럼 튀는 값이 있을 수 있는 데이터에 비교적 안정적)
11-2. AdamW: 딥러닝에 자주 쓰이는 optimizer 
	(일반 Adam보다 weight decay처리가 더 안정적이라 과적합 방지에 좋음)
11-3. ReduceLROnPlateau: 검증 손실이 더 이상 줄어들지 않으면, learning rate를 줄임
	factor=0.5, patience=5 => 검증 성능이 5번 정도 정체되면 학습률을 절반으로 낮춤
11-4. Gradient Clipping: gradient가 너무 커지는 것을 방지
	torch.nn.utils.clip_grad_norm_(self.model.parameters(), max_norm=1.0)
	(LSTM 같은 시계열 모델에서 학습이 불안정해지는 것을 줄이는 데 도움)

(예를 들어 seq_len = 4이고 특정 grid의 데이터가 다음처럼 있다고 해보겠습니다.
	t1, t2, t3, t4, t5, t6
그러면 다음과 같은 학습 샘플이 만들어집니다.
	[t1, t2, t3, t4] → t4의 correction_target

	[t3, t4, t5, t6] → t6의 correction_target
즉, 최근 4개 시점의 흐름을 보고 마지막 시점의 보정값을 맞히게 합니다.)

def combine_scores(base_score_df, correction_score_df, config): => Base Score + Correction Score
merged = correction_score_df.merge(base_score_df, on=config.grid_id_col, how="left") 
=> grid_id 기준으로 두 결과를 합침 => 그리고 다음 아래 계산 수행
merged["final_score"] = config.alpha * merged["base_score"] + config.beta * merged["correction_score"]

	timestamp
	grid_id
	base_score
	correction_score
	final_score

"우리가 정의한 기준 점수와 모델 예측이 얼마나 일치하는지 확인했다"로 보는 것이 더 정확

26. 이 코드의 한계와 주의점:
26-1. 서울 전역을 자동으로 예측하지는 않음
	이 코드는 입력 CSV에 들어 있는 grid만 예측
	따라서, base_infer.csv가 종로구 주변 grid만 가지고 있으면, 결과도 종로구 주변만 나옴
	서울 전역 결과를 원하면 다음이 필요
		서울 전역 grid_id
		서울 전역 grid 좌표
		서울 전역 grid별 base feature
		서울 전역 grid별 correction feature

26-2. 실시간 데이터는 122개 주요 장소 단위
	(서울 실시간 도시데이터 OpenAPI는 전 grid가 아니라 "주요 장소 단위")
	따라서 실시간 데이터를 grid에 적용하려면 다음 과정이 필요
		실시간 장소 데이터
 				↓
		place_id 또는 place_code 기준 정리
 				↓
		grid_place_mapping.csv로 grid 연결
 				↓
		장소 단위 값을 grid 단위로 분배
 				↓
		correction_infer.csv 형식으로 변환
	=> 실시간 API만 연결한다고 바로 서울 전역 grid 예측이 되는 것은 아님

26-3. correction_infer.csv는 시계열 길이가 필요:
	LSTM은 seq_len = 4이므로 grid별로 최소 4개 시점이 필요
	실시간 API에서 현재 시점 데이터 1개만 가져오면 바로 LSTM에 넣을 수 없음
	그래서, 실제 라이브 추론을 하려면 다음 방식이 필요:
	=> 과거 correction_infer 데이터 3개 시점 + 현재 실시간 API 데이터 1개 시점 = 총 4개 시점
	     이렇게 만들어야 LSTM 추론이 가능

26-4. final_actual은 실제 정답이 아닐 수 있음:
	=> 본 프로젝트의 평가는 실제 상권 성공 여부에 대한 완전한 정답 검증이라기보다, 
		정의한 적합도 기준에 대해 모델이 얼마나 일관되게 예측하는지 확인하는 방식이다.

27. 발표용으로 설명:
이 코드는 서울시 50m grid 단위 상권 활력도 예측 파이프라인입니다.
  먼저 과거 유동인구, 카드 소비, 강우량, 교통 접근성 등의 정적 feature를 이용해 MLP 기반 Base 모델을 학습하고, 
각 grid의 장기적 상권 적합도인 base_score를 산출합니다.
  이후 실시간 인구, 인구 증가율, 교통 혼잡도, 기온, 강우, 이벤트 여부 등의 시계열 feature를 LSTM 모델에 입력하여 
현재 시점의 보정값인 correction_score를 예측합니다.
  마지막으로 final_score = base_score + correction_score 방식으로 최종 상권 적합도 점수를 계산하고, 
이를 CSV와 히트맵 이미지로 저장합니다.
즉, 이 코드는 과거 데이터가 말해주는 평상시 상권 잠재력과 실시간 데이터가 말해주는 현재 상황을 결합해 
grid별 최종 추천 점수를 만드는 역할을 합니다.

28. 한 줄 요약:
이 코드는 서울시 grid별 상권의 “평상시 기본 점수”를 MLP로 예측하고, 
“현재 실시간 변화량”을 LSTM으로 보정한 뒤, 
최종 상권 적합도 점수와 히트맵을 생성하는 메인 딥러닝 파이프라인입니다.
